Mosquitto MQTT + ESP32-P4 面板接入 Home Assistant 实录

发表于 2026-10-18 分类于 硬件折腾 ， 智能家居 本文字数： 5.1k 阅读时长 ≈ 18 分钟
在 NanoPi R5C 上用 Docker 跑 Mosquitto 2.x，为 ESP32-P4 触摸面板与 Home Assistant 搭一条最小权限的 MQTT 通道：密码文件与 ACL、host 网络、mqtt_statestream 状态镜像、通用控制桥自动化，以及 ESPHome 端的订阅与线程坑。

本文基于 2026-10-18 的一次真实接入整理，Broker、HA 集成与端到端控制均已在实机跑通。
环境：NanoPi R5C / Armbian 13 / Docker 29.9 / Home Assistant 2026.10.2 (Container)，局域网 192.168.*.30

1. 目标：让面板和 HA 说上话

手上有一块 JC-ESP32P4-M3 触摸屏开发板，想把它当作家里的中控面板：按钮点一下能控制 HA 里的设备，屏幕上还能显示设备的当前状态。

方案没有走 HA 的 REST API，也没有在 P4 上跑复杂的 HTTP 客户端，而是用最省事的 MQTT：局域网里跑一个 Mosquitto，HA 和 P4 各自用独立账号连上去，靠主题约定分工。

需求 实现方式
HA 与 P4 通讯 局域网 Mosquitto Broker（1883），双方各一个账号
P4 控制 HA 设备 P4 发布 p4/cmd/<domain>/<object>/<service>，HA 自动化转发成服务调用
P4 显示设备状态 HA 的 mqtt_statestream 把状态镜像到 ha/<domain>/<object>/state（retain）
不让 P4 越权 ACL：p4 只能读 ha/#、读写 p4/#

2. 拓扑与端口规划

项目 值
Broker 地址（P4 用） 192.168.*.30:1883
Broker 地址（HA 用） 127.0.0.1:1883（HA 是 host 网络）
WebSocket 未开启（P4 不需要）
TLS 未启用（仅内网，见第 10 节）
配置文件 /opt/mosquitto/config/
数据 / 日志 /opt/mosquitto/data/、/opt/mosquitto/log/

一个常被问到的问题：为什么 HA 用 127.0.0.1 而不是局域网 IP？ 因为容器用了 network_mode: host，HA 容器里的 127.0.0.1 就是宿主机的 127.0.0.1，流量根本不经过网卡，省掉一层无谓的回环开销，也避免网卡切换时连接抖动。

3.2 目录：和 HA 分开

用绝对路径挂载，与 /opt/homeassistant 完全分开。好处很实际：备份 HA 的 config 时不会误带上 broker 的数据，两边升级、迁移也互不影响。

3.3 mosquitto.conf

/opt/mosquitto/config/mosquitto.conf：

几个配置项的取舍：

  • allow_anonymous false 必须配合 password_file，只写前者容器会直接起不来。
  • log_dest stdout 让日志走 docker logs，交给 /etc/docker/daemon.json 里已有的 10 MB × 3 轮转，不写 eMMC——这点对长期跑在 SD 卡 / eMMC 上的小主机很重要。
  • persistence true 把 retained 消息落盘。P4 依赖的“当前状态”本质就是 retained 消息，broker 重启后 P4 一订阅就能拿到值，不用等实体下次变化。
  • autosave_interval 300 比默认的 1800 秒短，掉电最多丢 5 分钟的状态快照，对 eMMC 的写入压力也可接受。
  • max_keepalive 120 限制客户端心跳上限，防止某个客户端协商出超长 keepalive 导致 broker 长时间挂着死连接。

3.4 ACL：让 P4 只能看，不能改

/opt/mosquitto/config/aclfile：

  • ha：MQTT 集成、设备发现、mqtt_statestream、控制桥都要用，索性给全量。
  • p4：只读 HA 的状态镜像；只能写自己的 p4/ 命名空间（命令、遥测、ESPHome 的 birth/debug 主题）。

这条规则的价值在“固件被改坏”的假设下才显现：即使 P4 上的程序出 bug、或者有人拿到了 P4 的账号，它也无法伪造 ha/... 状态去欺骗面板或 HA 的其它订阅者。权限边界画在 broker 上，比画在固件里可靠。

4. 权限设计：ACL 才是重点

回头单独说一下这块，因为它是整套方案里最容易被忽略、又最值钱的部分。

很多教程给 P4 直接开 topic readwrite #，图省事，能跑通。但那样意味着：面板固件可以往 homeassistant/... 发发现消息，凭空注册一个假设备；也可以往 ha/light/xxx/state 写任意值，让面板显示“灯开着”而实际关着。

4 秒的延迟主要来自“MQTT → 自动化触发 → 服务调用 → 设备响应 → 状态回流”这条链路，其中设备本身的响应占大头。局域网内这个量级对面板交互完全够用。

6.6 关于实体构成的一点观察

这台 HA 里 light/switch/fan/cover/climate 的实际构成挺有意思：

类型 数量 说明
climate.* 3 壁挂式空调（Midea）
light.* 8 绝大多数是设备指示灯 / 氛围灯，其中 5 个 unknown/unavailable
switch.* 70+ 小米设备的子开关（摄像机 AI 检测、扫地机功能项等），不是物理开关

也就是说：列表里没有常规照明实体。如果你的目标是控制真正的灯或插座，先确认它们是否已经接入 HA，再谈面板按钮。P4 上的按钮直接填对应 entity_id 即可，桥不关心设备品牌——但前提是那个实体真实存在且可用。

8. ESP32-P4（ESPHome）侧

8.1 前提条件

  • ESPHome 里 P4 的写法是 variant: ESP32P4 + framework: esp-idf，且需要较新的版本（示例工程用 min_version: 2026.5.2）。版本太旧会直接报 esp_ldo / esp32_hosted 未知。
  • P4 没有内置 WiFi：靠封装里的 ESP32-C6 通过 esp32_hosted（SDIO）提供网络。
  • MIPI 屏需要 esp_ldo 给 DSI PHY 供电（常见 channel: 3、2.5V），再配 display: platform: mipi_dsi。
  • 这些板级配置沿用你现有工程即可，示例里只给占位注释。

8.4 两个实现细节

回调线程：ESP32 上 MQTT 回调运行在 esp-mqtt 的任务里，不是主循环。直接 lv_label_set_text 在实测中可用（ESPHome 自带组件也这么干），但如果面板复杂、出现偶发花屏或重启，改成“回调只写全局变量，interval 里刷新控件”即可。这是典型的“能用”和“稳”之间的取舍。

订阅只做一次：MQTTClientComponent::subscribe() 不去重，每次调用都会新增一条订阅，订阅表只增不减。所以：

  • 不要放在 on_connect 里——每次重连都会多加一条，跑一天能堆出几十条重复订阅，回调被重复执行。
  • 放在 on_boot，或只在首次连接时执行一次。
  • 重连后的重订阅由 ESPHome 组件自己完成，不用你操心。

9. 排错速查

现象 原因 处理
容器起不来，日志 Unable to open pwfile passwd 属主是 root chown 1883:1883 + chmod 640
docker pull eclipse-mosquitto:2 超时 Docker Hub 不可达 用镜像站拉 + docker tag
HA 报 Connection refused broker 没起 / 端口不对 ss -tlnp | grep 1883
P4 一直重连 账号密码错 / ACL 拒绝发布 docker logs mosquitto 看 not authorised
P4 订阅 ha/# 收不到 mqtt_statestream 没配，或 domain 不在 include 检查 configuration.yaml，重启 HA
P4 上电后状态是 -- statestream 不发初始值 等实体变化，或靠启动补发自动化
控制没反应 实体名 / 服务名写错，或被 condition 挡掉 开发者工具 → 模板里跑 states('light.keting')
ESPHome 编译报 esp_ldo / esp32_hosted 未知 ESPHome 版本太旧 升级到 2026.5+
P4 能连 broker 但 HA 收不到命令 HA 里没加 MQTT 集成 见 6.1
面板回调重复执行 订阅加在了 on_connect 改到 on_boot，只订阅一次

排错的顺序建议是：先 broker，再 HA，最后 P4。broker 用 mosquitto_sub 能收到就说明网络和认证没问题；HA 侧用开发者工具能手动调服务就说明集成和实体没问题；剩下的才轮到固件。

10. 安全与维护

边界

  • 1883 不要映射到公网。 外网访问走 Tailscale / WireGuard 之类的隧道，或者至少上 TLS（listener 8883 + cafile/certfile/keyfile）。

  • p4 账号权限已最小化。如果面板只控制固定几台设备，可以把 ACL 从“读整个 ha/#”收窄到具体主题：

    这样即使 P4 完全失陷，攻击面也只有这两三个灯。

日常

  • 换密码：mosquitto_passwd 改完 docker restart mosquitto，再同步改 HA 集成和 ESPHome 的 secrets.yaml。三处必须一起改，漏一处就是“P4 一直重连”。

  • 备份：/opt/mosquitto 不在原有 HA 备份脚本范围内。retained 状态丢了会自动重建（靠启动补发），但配置建议单独备份：

  • 升级：docker compose pull mosquitto && docker compose up -d mosquitto。2.x 内部小版本可以直接升，跨大版本前先看 release notes 里 ACL 和配置项的变化。

  • 别把密码写进 compose 或 Git：凭据放本地文件或密码管理器，secrets.yaml 加进 .gitignore。

11. 写在最后

整套东西配置下来不到一小时，真正花时间的是把权限边界想清楚，以及验证它确实拦得住。四条测试用例里，前三条是“能用”，第四条才是“安全”——很多人只测前三条。

另一个感受是 mqtt_statestream + 通配符订阅这个组合的性价比很高：HA 侧几乎零代码（一段 YAML + 两条自动化），P4 侧也不用为每台设备写协议适配，toggle / turn_on / turn_off 这些服务名天然就是通用的。新增设备基本只是复制一个按钮、改四个值。

接下来准备把 P4 真正烧进去，接上实体跑一轮完整交互。ESPHome 那段 lv_label_set_text 在回调里是否稳定，还得在真实面板上多看几天。

唯一要提醒的是：文章里所有密码、ID、令牌都换成了占位符，你照抄的时候记得改。 尤其是长期访问令牌，它和密码等价，别顺手贴进任何一个公开的地方。
