1. 背景与结论

为什么不是 HAOS / Supervised

Home Assistant 官方在 2025-05 宣布废弃 Core 与 Supervised 安装方式，自 2025.12 版本起不再提供支持，长期只保留两种方式：

方式 说明 R5C 可行性
HAOS 官方整机镜像，带附加组件商店 ❌ 无 RK3568/R5C 官方镜像
HA Container 官方 Docker 镜像，附加组件自行用容器替代 ✅ 本文采用
Supervised 自建系统 + Supervisor ⚠️ 已废弃，Debian 13 上坑多，不建议
Core (venv) Python 虚拟环境直跑 ⚠️ 已废弃，不建议

最终成果

项目 结果
Home Assistant 2026.10.2，Container 版，http://192.168.*.30:8123
网络 有线静态 IP + WiFi 静态 IP 双通道（互为备份管理入口）
蓝牙 RTL8822CE，BLE 被动扫描可用
备份 每周日 04:00 自动打包 /config，保留 14 天
内核 已 apt-mark hold，避免滚动升级变砖

5.2 关键坑：不要新建 netplan 文件

Armbian 默认文件用 match: name: "e*" 一把抓所有以太网口。如果另建一个 enP1p17s0 的 yaml，netplan 会生成两个 .network，而 networkd 只认字典序第一个匹配文件（all-eth-interfaces 排在前面），结果是”改了不生效”。

✅ 正确做法：直接改原来那个文件，把通配 match 换成显式网口。

9.4 三个常见误解

现象 真相
手机在系统蓝牙里连不上这块板子 正常。板子没暴露 A2DP/HID/PAN 服务，手机配对必然失败。HA 只用 BLE 被动扫描，从不”连接”手机
添加集成时提示”未找到未配置的蓝牙适配器“ 正常。HA 启动时已通过 integration_discovery 自动创建了条目，去「设备与服务」页面找现成的 Bluetooth 卡片即可
日志里 BleakDBusError: No discovery started 无害。容器重启时要停一个本来没在跑的扫描，每台容器版 HA 重启都会出现

HA 用 SQLite（config/home-assistant_v2.db）。运行中直接 tar 会拷到不一致的数据库文件。正确做法只有两种：

  2. sqlite3 ... ".backup" 在线备份（麻烦，一般不必）

10.5 必须离机

13. 故障排查速查表

现象 原因 处理
curl -I http://ip:8123 返回 405 HA 不接受 HEAD 正常，改用 curl -s -o /dev/null -w '%{http_code}'
容器反复重启，日志 Unsupported system page size 16K/64K 页内核 加 DISABLE_JEMALLOC: "true"
Error binding to 0.0.0.0:8123 [Errno 98] 端口被占 ss -tlnp | grep 8123
容器 Up 但 8123 不通 防火墙拦截 nft list ruleset | head -30
docker pull ghcr.io/... 卡死 ghcr 不可达 用 ghcr.nju.edu.cn 拉 + docker tag 改回官方名
docker run hello-world 超时 Docker Hub 不可达 不影响 HA，忽略或配 registry-mirrors
蓝牙 Missing NET_ADMIN/NET_RAW 缺 capabilities cap_add: [NET_ADMIN, NET_RAW]
添加蓝牙集成提示”未找到未配置的适配器” 已有自动创建的条目 去「设备与服务」找现成卡片
BleakDBusError: No discovery started 重启时的无害报错 忽略
改 netplan 后没生效 新建了同名匹配的第二个文件 只改原文件，别新增
netplan apply 报权限告警 配置文件不是 600 chmod 600 /etc/netplan/*.yaml
备份脚本中途退出、无 cron pipefail + tar | head 触发 SIGPIPE 检查时先写文件再 grep
HACS 装完 HA 里没有 zip 无顶层目录，文件散落 先 mkdir hacs 再解压
docker compose 命令不存在 用的是 Debian 仓库版 用 docker-compose，或换 docker-ce 源

15. 安全检查清单

  • HA 使用强密码，且已存入密码管理器
  • 8123 端口未映射到公网（外网访问走 HA Cloud / Tailscale / WireGuard）
  • SSH 已改用密钥登录，并考虑 PasswordAuthentication no
  • 备份有一份离开本机（NAS / 电脑 / 网盘）
  • 已 apt-mark hold 内核三件套
  • 记录关键信息：IP、SSH 端口、备份路径、内核版本、WiFi SSID
  • 若临时授权过他人的 SSH 公钥，事后清理：
    sed -i '/<备注>/d' /root/.ssh/authorized_keys
